MarkVault API docs

Every MarkVault instance provides the three sets of endpoints below. This document covers MarkVault 0.0.x (Agent API 1.1.0) and describes what the backend code actually does. The example responses come from a real instance, with sample names and descriptions translated into English.

Overview

API Entry point Authentication Suited to
Agent REST API /api/v1/agent/* API key Scripts, automation and AI agents. It has an OpenAPI contract, and its paths and fields are kept stable.
MCP POST /api/mcp API key MCP-capable clients, which discover and call the 13 built-in tools directly.
App API /api/v1/* Login session or API key Used by the web interface and the browser extension. It covers the most features but makes no compatibility promise and may change between versions.

Conventions

  • The base URL is the address of your instance, for example http://localhost:8787. All paths below are relative to it.
  • Request bodies use Content-Type: application/json and must be a single JSON object, no larger than 2 MiB by default.
  • Responses are UTF-8 encoded JSON. Every response under /api/ carries Cache-Control: no-store.
  • Times are UTC ISO 8601 strings with millisecond precision, for example 2026-11-17T10:51:30.946Z. IDs are UUID strings.
  • Cross-origin requests are limited to the same origin by default. Cross-origin clients running in a browser (including extensions) need their full origin added to the deployment option CORS_ALLOWED_ORIGINS. The * wildcard is not supported.

Resources served by every instance

Each instance serves the addresses below directly. You can hand them to an agent, an API client or a documentation generator.

Address Content
/openapi-agent.json OpenAPI 3.1 contract of the Agent REST API
/llms.txt Documentation index for agents
/markvault/SKILL.md Agent Skill: confirmation flow, safety boundaries and workflows
/markvault/references/api.md API reference bundled with the Skill
/markvault/scripts/markvault-client.mjs Zero-dependency command-line client for Node.js 22
/agent Integration guide page inside the instance

Getting started

  1. Sign in to your instance and create an API key under Settings → API & external access. Pick the template that suits the purpose: READ_ONLY, BASIC or FULL. The full key is shown only once, when it is created.
  2. Put the instance URL and the key into local environment variables. Do not write the key into a repository, a URL or a chat log.
  3. Call /api/v1/agent/me to check the connection and see which permissions the key has.
export MARKVAULT_BASE_URL="http://localhost:8787"
export MARKVAULT_API_KEY="mvk_live_..."

curl -sS "$MARKVAULT_BASE_URL/api/v1/agent/me" \
  -H "X-API-Key: $MARKVAULT_API_KEY"

Response

{
  "data": {
    "api_key": {
      "id": "d61e6838-a41f-41d5-ab29-d03784a62741",
      "permissions": ["bookmarks.read", "tags.read", "user.read"]
    },
    "user": {
      "id": "c11e1903-9354-4648-8b85-f1fe09d2b16d",
      "username": "demo",
      "email": null,
      "role": "admin",
      "created_at": "2026-11-01T02:59:36.195Z",
      "stats": { "total_bookmarks": 27, "pinned_bookmarks": 3, "total_tags": 14 }
    }
  }
}

If you would rather not write requests by hand, use the command-line client that every instance serves. It reads the URL and the key from the two environment variables above, and write commands must be given --confirm explicitly.

curl -sSO "$MARKVAULT_BASE_URL/markvault/scripts/markvault-client.mjs"

node markvault-client.mjs me
node markvault-client.mjs search "Docker" --limit 10
node markvault-client.mjs bookmarks --sort updated --page-size 20
node markvault-client.mjs create-tag "to-read" --confirm

Authentication

The API accepts two kinds of credentials: an API key for external programs, and the login session obtained by signing in to the web interface. The Agent REST API accepts both; MCP accepts API keys only.

API keys

  • Send the key in the X-API-Key: <key> request header. Authorization: Bearer <key> also works.
  • A key is mvk_live_ followed by 64 hexadecimal digits, 73 characters in total. The server stores only a hash, and lists show only the first 13 characters.
  • Each account can have at most 20 active keys. A key can be given an expiry time and can be revoked at any time.
  • The latest 100 call log entries are kept for each key: method, path (without query parameters), status code and source address.
  • A request with no credentials returns 401 (请先登录, "please sign in"). An invalid, expired or revoked key returns 401 (API Key 无效或已过期, "the API key is invalid or has expired").

Login sessions

POST /api/v1/auth/login returns an access token and a refresh token. Later requests carry Authorization: Bearer <access_token>. 

curl -sS "$MARKVAULT_BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"your-password"}'

Response

{
  "data": {
    "access_token": "<access token>",
    "refresh_token": "<refresh token>",
    "token_type": "Bearer",
    "expires_in": 900,
    "user": {
      "id": "c11e1903-9354-4648-8b85-f1fe09d2b16d",
      "username": "demo",
      "email": null,
      "role": "admin",
      "created_at": "2026-11-01T02:59:36.195Z"
    }
  }
}
  • By default the access token expires after 15 minutes and the refresh token after 30 days. The deployment options JWT_ACCESS_TOKEN_EXPIRES_IN and JWT_REFRESH_TOKEN_EXPIRES_IN set these.
  • Once the access token has expired, submit {"refresh_token": "…"} to POST /api/v1/auth/refresh to get a new pair of tokens. Each refresh token can be used only once; submitting it again returns 401.
  • A login session has all the permissions of the account. Managing API keys, importing and exporting, changing preferences, managing plugins and the in-app chat accept login sessions only. Calling them with an API key returns 403 (此操作需要登录凭据, "this action requires login credentials").

Permissions

Each API key carries a set of permissions, and every endpoint checks the ones it needs. bookmarks.*, tags.* and tab_groups.* are wildcards that stand for all permissions of that resource.

Permission Allows
user.read Read account information and collection statistics
user.preferences.read Read interface preferences
bookmarks.read List, search and read bookmarks, check for duplicates, read snapshots, record clicks, read statistics
bookmarks.create Create bookmarks, create in batches, save snapshots and screenshots
bookmarks.update Edit and restore bookmarks, organise in batches, reorder pinned bookmarks, delete snapshots, replace or delete screenshots
bookmarks.delete Move to the trash, delete permanently, empty the trash
tags.read List and read tags, record tag clicks
tags.create Create tags
tags.update Change a tag's name, color and icon
tags.delete Delete tags
tags.assign Attach tags to bookmarks or detach them. tags.* includes it
tab_groups.read List and read tab groups, read share status and statistics
tab_groups.create Create tab groups
tab_groups.update Edit and restore tab groups, add, edit and move tabs, set up or cancel sharing
tab_groups.delete Delete tab groups and tabs
ai.suggest Used when a third-party plugin's tool needs to call a model

When creating a key you can pick a template directly:

Template Permissions included
READ_ONLY bookmarks.read, tags.read, user.read
BASIC (default) bookmarks.create, bookmarks.read, tags.create, tags.read, tags.assign, user.read
FULL bookmarks.*, tags.*, tab_groups.*, ai.suggest, user.read

Write permissions do not include read permissions. When a key without bookmarks.read creates or edits a bookmark, the response contains only the ID:

{ "data": { "bookmark": { "id": "b120a6f8-fe2e-40eb-a54e-ac765b3aa997" }, "already_exists": false, "restored": false } }

The same rule applies to the write endpoints for tags and tab groups.

Responses and errors

On success the data is in data. A successful create returns 201, and a successful delete returns 204 with no response body.

{ "data": { "tag": { "id": "a03fa48f-a693-49e1-9d81-7cd79a7b20d7", "name": "docs-sample" } } }

On failure an error object is returned. message is a description for people, written in Chinese; programs should decide by the status code and code.

{ "error": { "code": "INSUFFICIENT_PERMISSIONS", "message": "API Key 缺少权限: bookmarks.create" } }
Status code Meaning
400 BAD_REQUEST A parameter is missing or malformed, or the request body has an unknown field
401 UNAUTHORIZED No credentials; the API key is invalid, expired or revoked; the access token is no longer valid
403 INSUFFICIENT_PERMISSIONS The API key lacks a permission this action needs; message names the missing one
403 FORBIDDEN The endpoint accepts login sessions only; or the cross-origin source is not on the allow list
404 NOT_FOUND The target does not exist or does not belong to the current account
405 METHOD_NOT_ALLOWED The path exists but does not support this request method
409 CONFLICT A duplicate name or URL; or the feature has been turned off in the settings
413 REQUEST_ENTITY_TOO_LARGE The request body or file exceeds the limit; or the storage quota is insufficient
429 TOO_MANY_REQUESTS Rate limited; wait as the Retry-After response header says, then retry
500 INTERNAL_ERROR Server error; do not retry in a tight loop

Rate limits

  • Each API key is allowed at most 300 requests per 60 seconds, counted across REST and MCP together. One batch MCP request counts as one.
  • Beyond that the response is 429, and the Retry-After response header gives the seconds left in the current window.
  • The current version does not return X-RateLimit-* response headers. Clients only need to handle 429 and Retry-After.

A few endpoints have limits of their own:

Endpoint Limit
Login 10 per minute per source address; a username is locked temporarily after 20 failures within 15 minutes
Registration 5 per hour per source address
Token refresh 30 per minute per source address
Click recording 240 per minute per account, counted across bookmarks and tags together
Click analytics 120 per minute per account
In-app chat 20 per minute per account
Import 10 per hour per account, and only one import job at a time

The prefix is /api/v1/agent. The endpoints in the table below are part of the OpenAPI contract (/openapi-agent.json); long-lived integrations should depend only on them. Except for the capability index, the endpoints require Agent REST API to be enabled under Settings → API & external access, and return 409 while it is turned off.

GET/api/v1/agent/me user.read Check the connection and read account statistics
GET/api/v1/agent/search bookmarks.read Search bookmarks and tags
GET/api/v1/agent/bookmarks bookmarks.read List bookmarks with paging, filters and sorting
POST/api/v1/agent/bookmarks bookmarks.create Create a bookmark
GET/api/v1/agent/bookmarks/{id} bookmarks.read Read a bookmark

DELETE/api/v1/agent/bookmarks/{id} bookmarks.delete Move to the trash
PATCH/api/v1/agent/bookmarks/{id}/restore bookmarks.update Restore from the trash
GET/api/v1/agent/tags tags.read List tags with their bookmark counts
POST/api/v1/agent/tags tags.create Create a tag

PATCH/api/v1/agent/tags/{id} tags.update Edit a tag
DELETE/api/v1/agent/tags/{id} tags.delete Delete a tag

The REST write endpoints have no confirmation field: a request is executed as soon as it arrives. When an AI agent calls a write endpoint, the agent should show the user the exact action and get their consent before sending the request. The Skill that every instance serves (/markvault/SKILL.md) is written around this flow.

GET/api/v1/agent/meuser.read

Returns account information and collection statistics. When called with an API key it also returns the key's ID and permission list, which makes it a good way to check the permission boundary before starting work. For an example response see Getting started.

GET/api/v1/agent/searchbookmarks.read

Matches substrings in the title, description and URL of bookmarks and in the names of their tags, and also returns tags whose names match. Bookmarks in the trash are not searched.

Parameter Description
q Required. The search term; it must not be empty after leading and trailing whitespace is removed
limit The maximum number of bookmarks and of tags to return, 1–100, default 20

Bookmarks are ordered with pinned ones first, then by creation time, newest first. When the key lacks tags.read, results.tags is an empty array. 

curl -sS -G "$MARKVAULT_BASE_URL/api/v1/agent/search" \

  --data-urlencode "q=git" \
  --data-urlencode "limit=1"

Bookmarks

The bookmark object

Field Type Description
id string Bookmark ID
title string Title
url string URL. Unique within an account, counting bookmarks in the trash as well
description string | null Note
cover_image, favicon string | null Addresses of the cover image and the site icon
is_pinned, is_archived, is_public boolean Whether the bookmark is pinned, archived, public. Public bookmarks appear on the share page
pin_order integer Order among pinned bookmarks
click_count, last_clicked_at integer, string | null Click count and the time of the latest click
has_snapshot, snapshot_count, latest_snapshot_at boolean, integer, string | null Summary of the web page snapshots
screenshot object | null The image card made by the browser extension, at most one per bookmark: id, url, width, height, file_size, mime_type, created_at. url is a signed relative address valid for 1–2 hours, issued again each time the bookmark is read
tags array The bookmark's tags; each item has id, name, color
created_at, updated_at string Creation time and time of the latest change
deleted_at string | null The deletion time while the bookmark is in the trash, otherwise null

Responses may contain fields not listed here. Clients should ignore fields they do not recognise.

GET/api/v1/agent/bookmarksbookmarks.read

Lists bookmarks page by page, excluding the trash. Pinned bookmarks always come first; the rest are in descending order of the field named by sort.

Parameter Description
keyword Searches the title, description and URL; at most 500 characters
tags Comma-separated tag IDs. When several are given, a bookmark must have all of them
sort created (default, by creation time), updated (by modification time), popular (by click count). pinned is also accepted and behaves like created
pinned true returns only pinned bookmarks, false only unpinned ones
page_size Items per page, default 100. Values below 1 are treated as 1 and values above 200 as 200
page_cursor The next_cursor from the previous page's response, passed back unchanged

The backend also accepts two boolean filters, archived and public, which are not part of the OpenAPI contract.

The meta of the response:

Field Description
page_size, count The page size actually used, and the number of items returned on this page
has_more Whether more data follows
next_cursor The cursor for the next page, or null when there is none
related_tag_ids When filtering by tags, the other tags carried by the matching bookmarks, which can be used to narrow the results further. An empty array when tags is not used

next_cursor is an opaque string; do not parse or modify it. It contains quotation marks and other special characters, so it must be URL-encoded when placed in a query parameter, for example with curl's --data-urlencode. 

curl -sS -G "$MARKVAULT_BASE_URL/api/v1/agent/bookmarks" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  --data-urlencode "sort=updated" \
  --data-urlencode "page_size=20" \
  --data-urlencode "page_cursor=$NEXT_CURSOR"

Response (bookmark contents omitted)

{
  "data": {
    "bookmarks": [],
    "meta": {
      "page_size": 20,
      "count": 20,
      "has_more": true,
      "next_cursor": "<opaque cursor>",
      "related_tag_ids": []
    }
  }
}

POST/api/v1/agent/bookmarksbookmarks.create

Field Description
title Required. The title, 1–500 characters
url Required. An http or https address, at most 2000 characters, without a user name or password
description Note, at most 1000 characters
cover_image, favicon http or https addresses of the cover image and the site icon
tags An array of tag names, at most 30 items. Names that do not exist are created automatically. Needs tags.assign; creating new tags also needs tags.create

Any other field in the request body returns 400. There are three outcomes, depending on whether the URL already exists:

Case Status Result
The URL is new 201 The bookmark is created. already_exists and restored are both false
The URL is already saved 200 already_exists: true. The existing bookmark is returned and is not changed by the submitted content
The URL is in the trash 201 The bookmark is restored and overwritten with the submitted content, restored: true. Needs bookmarks.update. Its original tags are kept when neither tags nor tag_ids is submitted

GET/api/v1/agent/bookmarks/{id}bookmarks.read

Returns { "data": { "bookmark": { … } } }. Bookmarks in the trash can be read too, in which case deleted_at is not null. Returns 404 when the bookmark does not exist.

PATCH/api/v1/agent/bookmarks/{id}bookmarks.update

Submit only the fields to change; the rest stay as they are. The available fields are the same as for creation, plus is_archived.

  • Passing null for description, cover_image or favicon clears it.
  • tags or tag_ids replaces the bookmark's tags as a whole; an empty array clears them. The permission requirements are the same as for creation.
  • Changing url to one that another bookmark already uses returns 409; bookmarks in the trash count as using their URL.
  • A bookmark in the trash cannot be edited and returns 404; restore it first.
curl -sS -X PATCH "$MARKVAULT_BASE_URL/api/v1/agent/bookmarks/$BOOKMARK_ID" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title": "MarkVault docs", "is_public": true}'

Returns 200 and the updated { "data": { "bookmark": { … } } }.

DELETE/api/v1/agent/bookmarks/{id}bookmarks.delete

Moves the bookmark to the trash and returns 204. This is a soft delete that can be undone, but the bookmark's click count is reset to zero. Returns 404 when the bookmark is already in the trash. Permanent deletion is not part of the Agent API contract.

PATCH/api/v1/agent/bookmarks/{id}/restorebookmarks.update

Restores the bookmark from the trash and returns 200 with the restored bookmark. Returns 404 when the bookmark is not in the trash. No request body is needed.

POST/api/v1/agent/tagstags.create

Field Description
name Required. The name, 1–50 characters

Returns 201 and { "data": { "tag": { … } } }. Returns 409 when the name already exists.

curl -sS "$MARKVAULT_BASE_URL/api/v1/agent/tags" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  -H "Content-Type: application/json" \

GET/api/v1/agent/tags/{id}tags.read

Returns a single tag, including bookmark_count.

PATCH/api/v1/agent/tags/{id}tags.update

Changes name or color; submit only the fields to change. Returns 409 when the new name duplicates another tag.

DELETE/api/v1/agent/tags/{id}tags.delete

Deletes the tag, detaches it from its bookmarks and returns 204. The bookmarks themselves are not affected. Unlike bookmarks, a deleted tag cannot be restored.

MCP

MarkVault serves MCP as stateless Streamable HTTP, with JSON-RPC 2.0 messages. It provides tools only, not resources or prompts.

Connecting

Address POST <instance URL>/api/mcp
Authentication API keys only: X-API-Key or Authorization: Bearer <key>. Calling with a login session returns 401
Protocol versions 2025-06-18, 2025-03-26, 2024-11-05. initialize answers with the version the client asked for, and with 2025-06-18 for a version it does not recognise
Methods initialize, ping, tools/list, tools/call
Notifications Messages without an id (for example notifications/initialized) return 202 with no response body
Batches The request body may be an array of 1–100 messages; the response is then an array too
Response format application/json by default. When the Accept request header lists only text/event-stream, the response is a single SSE message event instead
Sessions There are no sessions and Mcp-Session-Id is not used; every request is authenticated on its own
Origin check When the request has an Origin header, the origin must be the instance itself or be listed in CORS_ALLOWED_ORIGINS; otherwise the response is 403

MCP server must be enabled under Settings → API & external access before use; requests return 409 while it is turned off.

To add it in Claude Code:

claude mcp add --transport http markvault "$MARKVAULT_BASE_URL/api/mcp" \
  --header "X-API-Key: $MARKVAULT_API_KEY"

For other clients that support Streamable HTTP, the configuration usually looks like the following. Check each client's documentation for the exact field names.

{
  "mcpServers": {
    "markvault": {
      "type": "http",
      "url": "https://bookmarks.example.com/api/mcp",
      "headers": { "X-API-Key": "mvk_live_..." }
    }
  }
}

Both methods write the key into the client's configuration file. Create a separate key for each client and grant it only the permissions it needs.

Tools

There are 13 built-in tools. tools/list returns only the tools the current key may use: a key made from the READ_ONLY template, for example, sees only the 6 read tools. Each tool's parameters are defined in the inputSchema returned by tools/list.

Tool Permission What it does
markvault_get_account user.read Reads the account and its bookmark and tag counts
markvault_search bookmarks.read Searches bookmarks and tags. Parameters query, limit
markvault_list_bookmarks bookmarks.read Lists bookmarks page by page. Parameters keyword, tag_ids (array), sort, pinned, page_size, page_cursor
markvault_get_bookmark bookmarks.read Reads a bookmark by id
markvault_create_bookmark bookmarks.create Write. Creates a bookmark, optionally attaching tags
markvault_update_bookmark bookmarks.update Write. Changes bookmark fields or replaces its tags
markvault_delete_bookmark bookmarks.delete Write. Moves a bookmark to the trash; it can be restored
markvault_restore_bookmark bookmarks.update Write. Restores a bookmark from the trash
markvault_list_tags tags.read Lists all tags with their bookmark counts
markvault_get_tag tags.read Reads a tag by id
markvault_create_tag tags.create Write. Creates a tag
markvault_update_tag tags.update Write. Changes a tag's name or color
markvault_delete_tag tags.delete Write. Deletes a tag permanently and detaches it; it cannot be restored
  • Write tools must be called with confirm: true. When it is missing or false, the tool refuses to run and returns 写操作需要用户确认 ("write actions need user confirmation"). Clients should pass it only after the user has clearly agreed to this particular action.
  • When a tool fails (insufficient permission, invalid parameters, missing confirmation, unknown tool), the response is still a successful JSON-RPC result, with isError set to true and the reason in structuredContent.error.
  • A JSON-RPC error is returned only for protocol-level problems: -32700 (the request body is not valid JSON; the HTTP status is also 400), -32600 (invalid message format), -32601 (unknown method), -32602 (invalid tools/call parameters).
  • Tool calls are counted under Statistics → Agent & MCP. Only the tool name, whether it succeeded and how long it took are recorded; parameters and returned content are not stored.

Initialize

curl -sS "$MARKVAULT_BASE_URL/api/mcp" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"example","version":"1.0.0"}}}'

The instructions string is returned in Chinese. It says that read tools can be called directly, while write actions need explicit user confirmation and confirm=true.

  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": { "tools": { "listChanged": false } },

    "instructions": "读取工具可直接调用；写操作需要用户明确确认并设置 confirm=true。"
  }
}

Calling a read tool

{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": { "name": "markvault_search", "arguments": { "query": "git", "limit": 1 } }
}

The result is given in two places: structuredContent is an object with the same content as the data of the matching REST endpoint, and content[0].text is the same data as a JSON string. 

{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{\"meta\":{\"bookmark_count\":1,\"tag_count\":0},\"query\":\"git\",\"results\":{…}}" }],

      "query": "git",
      "results": { "bookmarks": [{ "id": "0d18fc3b-ccd5-449a-8206-5238e94a0ec6", "title": "MarkVault" }], "tags": [] },
      "meta": { "bookmark_count": 1, "tag_count": 0 }

    "isError": false
  }
}

App API

These are the endpoints the web interface and the browser extension use, under the prefix /api/v1. They check API key permissions in the same way, but they are not a stable contract and may change between versions. Routes, permissions and key points are listed by resource below. Paths in the tables leave out the /api/v1 prefix unless the full path is written.

  • The bookmark, tag, tab group and statistics routes are also mounted under /api/tab (for older versions of the extension) and /api/v1/agent, and behave the same under all three prefixes. There is one exception: the create endpoint described under Bookmarks.
  • Endpoints marked "Login session" do not accept API keys.

Accounts and sessions

POST/api/v1/auth/refresh Public refresh_token. Returns a new pair of tokens

Public access

Endpoint Description
