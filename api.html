MarkVault 接口文档

每个 MarkVault 实例都自带下面三组接口。本文对应 MarkVault 0.0.x（Agent API 1.1.0），内容按后端代码的实际行为编写，示例响应来自真实实例。

概览

接口 入口 鉴权 适合
Agent REST API /api/v1/agent/* API Key 脚本、自动化和 AI Agent。有 OpenAPI 契约，路径和字段保持稳定。
MCP POST /api/mcp API Key 支持 MCP 的客户端，直接发现并调用 13 个内置工具。
应用接口 /api/v1/* 登录会话或 API Key 网页界面和浏览器扩展使用。功能最全，但不承诺兼容，升级时可能调整。

通用约定

  • 基础地址是你的实例地址，例如 http://localhost:8787，下文的路径都相对于它。
  • 请求体使用 Content-Type: application/json，必须是单个 JSON 对象，默认不超过 2 MiB。
  • 响应是 UTF-8 编码的 JSON。/api/ 下的响应都带 Cache-Control: no-store。
  • 时间是 UTC 的 ISO 8601 字符串，精确到毫秒，例如 2026-11-17T10:51:30.946Z。ID 是 UUID 字符串。
  • 跨域默认只允许同源。浏览器里的跨域客户端（包括扩展）需要把完整来源写进部署配置 CORS_ALLOWED_ORIGINS，不支持 * 通配。

快速上手

  1. 登录实例，在「设置 → API 与外部访问」创建 API Key。按用途选择模板：READ_ONLY、BASIC 或 FULL。完整的 Key 只在创建时显示一次。
  2. 把实例地址和 Key 放进本地环境变量。不要把 Key 写进仓库、URL 或聊天记录。
  3. 调用 /api/v1/agent/me 验证连接，并确认这个 Key 拥有哪些权限。
export MARKVAULT_BASE_URL="http://localhost:8787"
export MARKVAULT_API_KEY="mvk_live_..."

curl -sS "$MARKVAULT_BASE_URL/api/v1/agent/me" \
  -H "X-API-Key: $MARKVAULT_API_KEY"

响应

{
  "data": {
    "api_key": {
      "id": "d61e6838-a41f-41d5-ab29-d03784a62741",
      "permissions": ["bookmarks.read", "tags.read", "user.read"]
    },
    "user": {
      "id": "c11e1903-9354-4648-8b85-f1fe09d2b16d",
      "username": "demo",
      "email": null,
      "role": "admin",
      "created_at": "2026-11-01T02:59:36.195Z",
      "stats": { "total_bookmarks": 27, "pinned_bookmarks": 3, "total_tags": 14 }
    }
  }
}

不想手写请求时，可以用实例自带的命令行客户端。它从上面两个环境变量读取地址和 Key，写命令必须显式加 --confirm。

curl -sSO "$MARKVAULT_BASE_URL/markvault/scripts/markvault-client.mjs"

node markvault-client.mjs me
node markvault-client.mjs search "Docker" --limit 10
node markvault-client.mjs bookmarks --sort updated --page-size 20
node markvault-client.mjs create-tag "待读" --confirm

鉴权

接口接受两种凭据：给外部程序用的 API Key，和网页界面登录后得到的登录会话。Agent REST API 两种都接受，MCP 只接受 API Key。

API Key

  • 用请求头 X-API-Key: <key> 传递。也可以用 Authorization: Bearer <key>。
  • Key 形如 mvk_live_ 加 64 位十六进制，共 73 个字符。服务端只保存哈希，列表里只显示前 13 个字符。
  • 每个账号最多 20 个有效 Key。Key 可以设置过期时间，可以随时撤销。
  • 每个 Key 保留最近 100 条调用日志：方法、路径（不含查询参数）、状态码和来源地址。
  • 不带任何凭据时返回 401（请先登录）；Key 无效、过期或已撤销时返回 401（API Key 无效或已过期）。

登录会话

POST /api/v1/auth/login 返回访问令牌和刷新令牌。之后的请求带上 Authorization: Bearer <access_token>。 

curl -sS "$MARKVAULT_BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"你的密码"}'

响应

{
  "data": {
    "access_token": "<访问令牌>",
    "refresh_token": "<刷新令牌>",
    "token_type": "Bearer",
    "expires_in": 900,
    "user": {
      "id": "c11e1903-9354-4648-8b85-f1fe09d2b16d",
      "username": "demo",
      "email": null,
      "role": "admin",
      "created_at": "2026-11-01T02:59:36.195Z"
    }
  }
}
  • 访问令牌默认 15 分钟过期，刷新令牌默认 30 天，分别由部署配置 JWT_ACCESS_TOKEN_EXPIRES_IN 和 JWT_REFRESH_TOKEN_EXPIRES_IN 决定。
  • 访问令牌过期后，用 POST /api/v1/auth/refresh 提交 {"refresh_token": "…"} 换一对新令牌。每个刷新令牌只能用一次，用过后再提交会返回 401。
  • 登录会话拥有账号的全部权限。管理 API Key、导入导出、修改偏好、管理插件和站内聊天只接受登录会话，用 API Key 调用会返回 403（此操作需要登录凭据）。

权限

每个 API Key 带一组权限，接口逐项校验。bookmarks.*、tags.*、tab_groups.* 是通配写法，代表该资源下的全部权限。

权限 允许的操作
user.read 读取账户信息和收藏统计
user.preferences.read 读取界面偏好
bookmarks.read 列出、搜索和读取书签，查重，读取快照，记录点击，读取统计
bookmarks.create 创建书签，批量创建，保存快照和截图
bookmarks.update 修改和恢复书签，批量整理，调整置顶顺序，删除快照，替换或删除截图
bookmarks.delete 移入回收站，永久删除，清空回收站
tags.read 列出和读取标签，记录标签点击
tags.create 创建标签
tags.update 修改标签名称、颜色和图标
tags.delete 删除标签
tags.assign 给书签关联或解除标签。tags.* 包含它
tab_groups.read 列出和读取标签页组，读取分享状态和统计
tab_groups.create 创建标签页组
tab_groups.update 修改和恢复标签页组，添加、修改和移动标签页，设置或取消分享
tab_groups.delete 删除标签页组和标签页
ai.suggest 第三方插件的工具需要调用模型时使用

创建 Key 时可以直接选模板：

模板 包含的权限
READ_ONLY bookmarks.read、tags.read、user.read
BASIC（默认） bookmarks.create、bookmarks.read、tags.create、tags.read、tags.assign、user.read
FULL bookmarks.*、tags.*、tab_groups.*、ai.suggest、user.read

写入权限不包含读取权限。没有 bookmarks.read 的 Key 创建或修改书签后，响应里只有 ID：

{ "data": { "bookmark": { "id": "b120a6f8-fe2e-40eb-a54e-ac765b3aa997" }, "already_exists": false, "restored": false } }

标签和标签页组的写接口也是同样的规则。

响应与错误

成功时，数据放在 data 里。创建成功返回 201，删除成功返回 204 且没有响应体。

{ "data": { "tag": { "id": "a03fa48f-a693-49e1-9d81-7cd79a7b20d7", "name": "文档示例" } } }

失败时返回 error 对象。message 是给人看的中文说明，程序请按状态码和 code 判断。

{ "error": { "code": "INSUFFICIENT_PERMISSIONS", "message": "API Key 缺少权限: bookmarks.create" } }
状态码 code 含义
400 BAD_REQUEST 参数缺失、格式无效，或请求体里有未知字段
401 UNAUTHORIZED 没有凭据；API Key 无效、过期或已撤销；访问令牌失效
403 INSUFFICIENT_PERMISSIONS API Key 缺少这次操作需要的权限，message 里写明缺的是哪一项
403 FORBIDDEN 接口只接受登录会话；或跨域来源不在白名单里
404 NOT_FOUND 目标不存在，或不属于当前账号
405 METHOD_NOT_ALLOWED 路径存在，但不支持这个请求方法
409 CONFLICT 名称或网址重复；或对应的功能已在设置里停用
413 REQUEST_ENTITY_TOO_LARGE 请求体或文件超过上限；或存储配额不足
429 TOO_MANY_REQUESTS 触发限流，按响应头 Retry-After 等待后再试
500 INTERNAL_ERROR 服务端错误，不要连续重试

限流

  • 每个 API Key 每 60 秒最多 300 次请求，REST 和 MCP 合并计数。一次批量 MCP 请求算一次。
  • 超出后返回 429，响应头 Retry-After 给出当前窗口还剩多少秒。
  • 当前版本不返回 X-RateLimit-* 响应头，客户端只需要处理 429 和 Retry-After。

个别接口另有独立的限制：

接口 限制
登录 每个来源地址每分钟 10 次；同一用户名 15 分钟内失败 20 次后暂时锁定
注册 每个来源地址每小时 5 次
刷新令牌 每个来源地址每分钟 30 次
记录点击 每个账号每分钟 240 次，书签和标签合并计数
点击分析 每个账号每分钟 120 次
站内聊天 每个账号每分钟 20 次
导入 每个账号每小时 10 次，同一时间只能有一个导入任务

Agent REST API

前缀是 /api/v1/agent。下表的端点写进了 OpenAPI 契约（/openapi-agent.json），长期集成请只依赖它们。除能力索引外，其余端点要求「设置 → API 与外部访问」里的 Agent REST API 处于启用状态，停用时返回 409。

端点 权限 用途
GET/api/v1/agent 无需鉴权 版本、文档地址和端点索引
GET/api/v1/agent/me user.read 验证连接，读取账户统计
GET/api/v1/agent/search bookmarks.read 搜索书签和标签
GET/api/v1/agent/bookmarks bookmarks.read 分页列出、筛选和排序书签
POST/api/v1/agent/bookmarks bookmarks.create 创建书签
GET/api/v1/agent/bookmarks/{id} bookmarks.read 读取书签
PATCH/api/v1/agent/bookmarks/{id} bookmarks.update 修改书签
DELETE/api/v1/agent/bookmarks/{id} bookmarks.delete 移入回收站
PATCH/api/v1/agent/bookmarks/{id}/restore bookmarks.update 从回收站恢复
GET/api/v1/agent/tags tags.read 列出标签和书签数量
POST/api/v1/agent/tags tags.create 创建标签
GET/api/v1/agent/tags/{id} tags.read 读取标签
PATCH/api/v1/agent/tags/{id} tags.update 修改标签
DELETE/api/v1/agent/tags/{id} tags.delete 删除标签

REST 写接口没有确认字段：请求到达就会执行。让 AI Agent 调用写接口时，应由 Agent 在发请求前向用户展示准确的操作并取得同意。实例自带的 Skill（/markvault/SKILL.md）就是按这个流程写的。

GET/api/v1/agent/meuser.read

返回账号信息和收藏统计。用 API Key 调用时，还会返回这个 Key 的 ID 和权限列表，适合在开始工作前确认权限边界。响应示例见快速上手。

GET/api/v1/agent/searchbookmarks.read

在书签的标题、描述、网址和所带标签的名称里做子串匹配，同时返回名称匹配的标签。回收站里的书签不参与搜索。

参数 说明
q 必填。搜索词，去掉首尾空白后不能为空
limit 书签和标签各自最多返回多少条，1–100，默认 20

书签按置顶优先、创建时间倒序排列。Key 没有 tags.read 时，results.tags 是空数组。 

curl -sS -G "$MARKVAULT_BASE_URL/api/v1/agent/search" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  --data-urlencode "q=git" \
  --data-urlencode "limit=1"

书签

书签对象

字段 类型 说明
id string 书签 ID
title string 标题
url string 网址。同一账号内不重复，回收站里的书签也算
description string | null 备注
cover_image、favicon string | null 封面图和站点图标的地址
is_pinned、is_archived、is_public boolean 是否置顶、归档、公开。公开的书签会出现在分享页
pin_order integer 置顶书签之间的顺序
click_count、last_clicked_at integer、string | null 点击次数和最近一次点击的时间
has_snapshot、snapshot_count、latest_snapshot_at boolean、integer、string | null 网页快照的概况
screenshot object | null 浏览器扩展生成的图文卡片，每个书签最多一张：id、url、width、height、file_size、mime_type、created_at。url 是带签名的相对地址，有效期 1–2 小时，每次读取书签时重新签发
tags array 书签的标签，每项有 id、name、color
created_at、updated_at string 创建和最近修改的时间
deleted_at string | null 在回收站里时是删除时间，否则是 null

响应里还可能有这里没列出的字段，客户端应当忽略不认识的字段。

GET/api/v1/agent/bookmarksbookmarks.read

分页列出书签，不含回收站。置顶的书签始终排在最前面，其余按 sort 指定的字段倒序。

参数 说明
keyword 在标题、描述和网址里搜索，最多 500 个字符
tags 逗号分隔的标签 ID。给出多个时，书签必须同时带有全部标签
sort created（默认，按创建时间）、updated（按修改时间）、popular（按点击次数）。pinned 也被接受，效果与 created 相同
pinned true 只返回置顶书签，false 只返回未置顶的
page_size 每页数量，默认 100。小于 1 按 1、大于 200 按 200 处理
page_cursor 上一页响应里的 next_cursor，原样传回

后端还接受 archived 和 public 两个布尔筛选参数，它们没有写进 OpenAPI 契约。

响应的 meta：

字段 说明
page_size、count 实际采用的每页数量，和本页返回的条数
has_more 后面是否还有数据
next_cursor 下一页的游标，没有下一页时是 null
related_tag_ids 用 tags 筛选时，符合条件的书签还带有哪些其他标签，可用来继续缩小范围。没有用 tags 时是空数组

next_cursor 是不透明的字符串，不要解析或修改。它含有引号等特殊字符，放进查询参数时必须做 URL 编码，例如用 curl 的 --data-urlencode。 

curl -sS -G "$MARKVAULT_BASE_URL/api/v1/agent/bookmarks" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  --data-urlencode "sort=updated" \
  --data-urlencode "page_size=20" \
  --data-urlencode "page_cursor=$NEXT_CURSOR"

响应（省略了书签内容）

{
  "data": {
    "bookmarks": [],
    "meta": {
      "page_size": 20,
      "count": 20,
      "has_more": true,
      "next_cursor": "<不透明游标>",
      "related_tag_ids": []
    }
  }
}

POST/api/v1/agent/bookmarksbookmarks.create

字段 说明
title 必填。标题，1–500 个字符
url 必填。http 或 https 地址，最长 2000 个字符，不能带用户名和密码
description 备注，最长 1000 个字符
cover_image、favicon 封面图和站点图标的 http 或 https 地址
tags 标签名称数组，最多 30 项。不存在的名称会自动创建。需要 tags.assign，创建新标签还需要 tags.create
tag_ids 标签 ID 数组，最多 30 项。需要 tags.assign。不能和 tags 同时提供
is_pinned、is_public 是否置顶、公开，默认都是 false

请求体里出现其他字段会返回 400。按网址是否已经存在，结果分三种：

情况 状态码 结果
网址是新的 201 创建书签。already_exists 和 restored 都是 false
网址已经收藏过 200 already_exists: true，返回已有的书签，不会用这次提交的内容修改它
网址在回收站里 201 恢复这个书签并用这次提交的内容覆盖，restored: true。需要 bookmarks.update。没有提交 tags 或 tag_ids 时保留原来的标签 
curl -sS "$MARKVAULT_BASE_URL/api/v1/agent/bookmarks" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "MarkVault 文档示例",
    "url": "https://example.com/markvault-docs-sample",
    "description": "用于演示接口返回值",
    "tags": ["文档示例", "待读示例"]
  }'

GET/api/v1/agent/bookmarks/{id}bookmarks.read

返回 { "data": { "bookmark": { … } } }。回收站里的书签也能读到，此时 deleted_at 不是 null。书签不存在时返回 404。

PATCH/api/v1/agent/bookmarks/{id}bookmarks.update

只提交要修改的字段，其余保持不变。可用的字段和创建时相同，另外多一个 is_archived。

  • description、cover_image、favicon 传 null 表示清空。
  • tags 或 tag_ids 会整体替换书签的标签，传空数组表示清空。权限要求和创建时相同。
  • 把 url 改成另一个书签已经占用的网址时返回 409，回收站里的书签也算占用。
  • 回收站里的书签不能修改，返回 404，需要先恢复。
curl -sS -X PATCH "$MARKVAULT_BASE_URL/api/v1/agent/bookmarks/$BOOKMARK_ID" \
  -H "X-API-Key: $MARKVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title": "MarkVault 文档", "is_public": true}'

返回 200 和修改后的 { "data": { "bookmark": { … } } }。

DELETE/api/v1/agent/bookmarks/{id}bookmarks.delete

把书签移入回收站，返回 204。这是可以恢复的软删除，但书签的点击次数会清零。书签已经在回收站里时返回 404。永久删除不在 Agent API 的契约里。

PATCH/api/v1/agent/bookmarks/{id}/restorebookmarks.update

把书签从回收站恢复，返回 200 和恢复后的书签。书签不在回收站里时返回 404。不需要请求体。

MCP

MarkVault 以无状态的 Streamable HTTP 方式提供 MCP 服务，消息格式是 JSON-RPC 2.0。它只提供工具（tools），不提供 resources 和 prompts。

连接

地址 POST <实例地址>/api/mcp
鉴权 只接受 API Key：X-API-Key 或 Authorization: Bearer <key>。用登录会话调用会返回 401
协议版本 2025-06-18、2025-03-26、2024-11-05。initialize 按客户端请求的版本应答，遇到不认识的版本时按 2025-06-18 应答
方法 initialize、ping、tools/list、tools/call
通知 不带 id 的消息（例如 notifications/initialized）返回 202，没有响应体
批量 请求体可以是 1–100 条消息组成的数组，响应也是数组
响应格式 默认是 application/json。请求头 Accept 只有 text/event-stream 时，改用一条 SSE message 事件返回
会话 没有会话，不使用 Mcp-Session-Id，每个请求独立鉴权
来源检查 带 Origin 请求头时，来源必须是实例自身或在 CORS_ALLOWED_ORIGINS 里，否则返回 403

使用前要求「设置 → API 与外部访问」里的 MCP 服务处于启用状态，停用时返回 409。

在 Claude Code 里添加：

claude mcp add --transport http markvault "$MARKVAULT_BASE_URL/api/mcp" \
  --header "X-API-Key: $MARKVAULT_API_KEY"

其他支持 Streamable HTTP 的客户端，配置大多是下面的形式。字段名以各客户端的文档为准。

{
  "mcpServers": {
    "markvault": {
      "type": "http",
      "url": "https://bookmarks.example.com/api/mcp",
      "headers": { "X-API-Key": "mvk_live_..." }
    }
  }
}

这两种方式都会把 Key 写进客户端的配置文件。请为每个客户端创建单独的 Key，只授予它需要的权限。

工具

内置 13 个工具。tools/list 只返回当前 Key 有权使用的工具：例如 READ_ONLY 模板的 Key 只能看到 6 个读取工具。每个工具的参数定义在 tools/list 返回的 inputSchema 里。

工具 权限 作用
markvault_get_account user.read 读取账户和书签、标签数量
markvault_search bookmarks.read 搜索书签和标签。参数 query、limit
markvault_list_bookmarks bookmarks.read 分页列出书签。参数 keyword、tag_ids（数组）、sort、pinned、page_size、page_cursor
markvault_get_bookmark bookmarks.read 按 id 读取书签
markvault_create_bookmark bookmarks.create 写。创建书签，可同时关联标签
markvault_update_bookmark bookmarks.update 写。修改书签字段或替换标签
markvault_delete_bookmark bookmarks.delete 写。把书签移入回收站，可以恢复
markvault_restore_bookmark bookmarks.update 写。从回收站恢复书签
markvault_list_tags tags.read 列出全部标签和书签数量
markvault_get_tag tags.read 按 id 读取标签
markvault_create_tag tags.create 写。创建标签
markvault_update_tag tags.update 写。修改标签名称或颜色
markvault_delete_tag tags.delete 写。永久删除标签并解除关联，不能恢复
  • 写工具必须带 confirm: true。缺少它或值为 false 时，工具拒绝执行并返回「写操作需要用户确认」。客户端应当在用户明确同意这次操作之后才传入。
  • 工具执行失败时（权限不足、参数无效、缺少确认、工具不存在），响应仍是成功的 JSON-RPC 结果，其中 isError 为 true，原因在 structuredContent.error 里。
  • 只有协议层面的问题才返回 JSON-RPC error：-32700（请求体不是合法 JSON，同时 HTTP 状态码为 400）、-32600（消息格式无效）、-32601（未知方法）、-32602（tools/call 的参数无效）。
  • 工具调用计入「数据统计 → Agent 与 MCP」。那里只记录工具名、是否成功和耗时，不保存参数和返回内容。

应用接口

网页界面和浏览器扩展使用的接口，前缀是 /api/v1。它们同样校验 API Key 的权限，但不属于稳定契约，升级时可能调整。下面按资源列出路由、权限和要点；表格里的路径省略了 /api/v1 前缀，除非写出了完整路径。

  • 书签、标签、标签页组和统计这几组路由，同时挂在 /api/tab（兼容旧版扩展）和 /api/v1/agent 两个前缀下，行为相同。只有一处例外，见书签里的创建接口。
  • 标注「登录会话」的接口不接受 API Key。

账号与会话

接口 鉴权 说明
POST/api/v1/auth/register 公开 注册。username（3–20 位字母、数字或下划线）、password（8–1024 字节）、可选的 email。首个账号成为管理员，之后注册自动关闭
POST/api/v1/auth/login 公开 username、password。返回令牌和用户信息，见登录会话
POST/api/v1/auth/refresh 公开 refresh_token。返回一对新令牌
POST/api/v1/auth/logout 登录会话 refresh_token。加上 revoke_all: true 会注销这个账号的全部会话。返回 204
