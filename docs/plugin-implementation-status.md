## 仍需完成的原方案项目

1. 现有 Agent 协议适配与业务执行函数仍有部分位于 internal/server，已通过注册与停用门控接入；还未完成全部具体实现向 plugins/ 的物理拆分及纯接口装配。
2. 生命周期注册表已实现并测试，但当前服务端脚本采用每次调用独立启动/销毁；未接入安装/升级生命周期回调、长期任务与完整依赖启动流程。
3. 前端内置 React 实现尚未全部改成按需注册加载；实验功能上下文仍有兼容映射。背景扩展目前使用固定面板位置，并非完整的全屏交互画布层。
4. 社区主题只支持设计变量，不接收任意 CSS；第三方 HTML 必须自包含。包内独立脚本/图片资源重写及社区发布审核流程尚未交付。
5. 外部 MCP 当前使用每次调用独立会话与执行前刷新，不持有长期 SSE 订阅；未实现自动 listChanged 推送刷新、只读工具免确认选项以及完整断线重连策略。
6. 模型适配器沿用 100 秒聊天总时限；128 MiB 限制是 V8 堆限制，不等价于完整进程 RSS 硬限制。对不可信插件的高保证部署仍需 OS/容器资源限额验证。
7. 自定义目录刷新与固定 Release 下载已实现，但未使用真实远端示例 Release 完成端到端安装验收；官方在线目录服务尚未发布。离线市场与 ZIP 路径已实际验证。
8. 本机 Docker 引擎未启动，linux/amd64、linux/arm64 镜像尚未构建和启动验收。主 Dockerfile 已加入固定摘要的 Deno；scratch 预构建镜像仍不包含脚本运行时。
9. CI 已加入运行时和真实浏览器检查。本批提交版本为 1.2.1010；远端 CI 和镜像发布结果以对应工作流为准，版本号递增不代表镜像已发布。

继续实施时应优先完成上述集成及验收，再将完整五阶段标记完成。搜索栏原有改动与 .pi/ 内容保持原样，未修改独立扩展仓库。

1.2.1021 推送后，「代码检查」工作流通过，但镜像工作流里同一份检查的浏览器插件集成测试连续两次超时，镜像没有发布。原因在测试脚本：目录条目和管理员身份是异步加载的，脚本在页面标题出现后立刻判断有没有「安装」按钮，按钮还没渲染时会跳过安装，然后一直等不到「已安装」。1.2.1022 改为先等按钮出现再判断，失败时把页面提示和目录卡片状态打进日志。本地在全新实例上把目录接口延迟 1.5 秒：旧脚本报出与 CI 相同的超时，新脚本在有延迟和无延迟时都通过。产品代码没有改动。
1.2.1022 推送后镜像发布成功，但「代码检查」工作流的浏览器插件集成测试在另一处失败：刷新插件便笺页后读到的内容与保存值不一致。原因仍在测试脚本：便笺页先渲染空文本框，再异步从插件存储读回内容，脚本在文本框出现后立刻读取，读取比存储接口返回早时拿到空值。1.2.1023 改为等内容回填后再比较；同时补上原先只收集、没有断言的检查，直接确认父页伪造的消息没有触发插件接口请求。本地在全新实例上把插件接口延迟 1.5 秒：旧脚本报出与 CI 相同的错误，新脚本在有延迟和无延迟时都通过，无延迟连续三次通过；让 iframe 自己发出同样的写入时，新增的断言会报错。产品代码没有改动。
