# Agent 与 MCP 使用统计

登录后打开「数据统计」，切换至「Agent 与 MCP」，可按日期、用户时区、日／周／月粒度和来源查看调用次数、成功率、平均耗时、活跃天数、调用趋势及工具／接口排行。标签和书签筛选仅作用于点击统计。

## 统计口径

- 站内 Agent：一次聊天、确认或取消请求计一次调用；每次实际尝试执行的工具另计入工具调用数。待确认的写操作和取消操作不计为工具执行。
- Agent API：鉴权通过后进入 `/api/v1/agent/*` 的 REST 请求计一次调用，按 HTTP 结果判断成功。公开能力索引和普通 `/api/v1/*` 请求不计入。
- MCP：每个带请求 ID 的 `tools/call` 计一次工具调用，批次逐项记录。参数、权限及确认失败也计为失败；握手、心跳、工具列表及通知不计入。成功与否依据工具执行结果，不能仅看 HTTP 200。
- 总调用量不重复累加站内 Agent 的内部工具；工具调用指标汇总站内 Agent 与 MCP，因此不能与总调用量相加。
- 平均耗时包含成功和失败调用，按调用数加权；请求成功不代表回复质量，也不保证聊天内部所有工具均成功，工具失败可在排行中查看。
- 无调用时成功率和耗时显示「—」。明细从升级后开始记录，不能从仅保留最近 100 条的 API Key 日志可靠补录历史。

## 数据与接口

服务启动时自动应用 `0125_agent_usage.sql`，创建 `agent_usage_events` 与用户／时间索引，无需额外配置。只保存用户归属、来源、调用类型、工具名或路由模板、成功状态、耗时和开始时间，不保存对话、参数、资源 ID、API Key 或响应内容。删除账号时级联删除，撤销 API Key 不清除历史使用统计。统计写入失败会记录服务端警告，不改变业务请求结果。

`GET /api/v1/analytics/agent` 仅允许本人登录凭据访问，API Key 不可读取账号级统计。参数包括 `start_date`、`end_date`、`tz`、`granularity`、`limit`、`source`（`all`、`chat`、`agent_api`、`mcp`）；日期和粒度规则与点击统计一致。省略起始日期时，从所选来源最早调用开始，最多 3660 天。无数据日期补零，按时区处理跨日和夏令时。

该接口不支持 `tag_id`、`bookmark_id`。响应契约维护于 `shared/agent-usage-types.ts`。统计数据仅限当前账号；接口采用独立的每分钟 120 次限流。
