# MarkVault 插件体系改造方案

## 目标与范围

把 MarkVault 改造成具有统一插件协议、插件中心和运行时的应用，支持**内置插件、官方插件、社区插件**。借鉴 Magpie 的模块注册、生命周期、扩展位置、工具注册和插件分发机制，使用 MarkVault 自己的 SDK。

本次完整范围包括：

- 将主题、配色、动效、海洋背景、实验视觉效果、站内 Agent、模型适配器、Agent API 和 MCP 服务迁成内置插件。
- 支持第三方 JavaScript/TypeScript 插件贡献页面、设置面板、菜单动作、主题、动效、模型供应商、Agent 和工具。
- 支持插件市场、GitHub Release、离线 ZIP 安装，以及外部 MCP 的 HTTP/SSE 连接。
- 管理员控制实例安装与可用范围；用户独立启用、配置和授权。

账号认证、权限检查、书签、标签、标签页组、快照、数据库、文件存储和插件管理保留为核心服务。本轮不迁移全部业务模块，不兼容 Magpie/OpenCode 插件协议，不支持直接安装 npm 包或运行 stdio MCP 命令。

## 架构与公共接口

### 统一插件协议

在 `shared/plugin-manifest.schema.json` 定义清单协议，并以同一批契约样例验证 Go 与 TypeScript 实现。清单包含插件 ID、版本、宿主 API 兼容范围、名称、作者、入口、依赖、权限、设置 Schema 和扩展声明。

- `contributes` 支持主题、动效、背景、页面、面板、菜单动作、模型供应商、Agent、工具和 MCP 连接模板；一个插件可以提供多种能力。
- 内置／官方／社区身份由宿主根据随程序分发的注册信息和可信目录确定，不能由插件自行声明。
- 生命周期统一为安装、启用、等待依赖、运行、失败、停用、卸载；依赖按拓扑顺序启动，释放按逆序执行，拒绝依赖环和重复注册。
- 禁用时撤销该插件的页面、样式、监听器、工具与任务。缺失依赖时显示具体原因，不偷偷启用未经授权的依赖。

后端插件内核放入 `internal/plugin`，前端注册与扩展组件放入 `src/plugins`。具体内置插件由应用启动入口装配，核心服务不反向依赖插件实现。

### 执行宿主与权限

服务端脚本采用固定版本的 Deno，初始锁定已核查的 **2.9.8**，下载产物校验摘要。Docker 镜像内置运行时；原生部署可配置运行时路径，缺失时核心和原生内置插件照常工作，脚本插件显示“运行时不可用”。

- 每个“用户＋插件”按需启动独立进程，插件代码放入无系统权限的 Worker；可信引导程序负责与 Go 进行 JSON-RPC 通信。
- 作者将依赖打包为自包含 JavaScript 产物。安装和运行期间不执行安装脚本、不下载依赖、不加载包外模块。
- 插件不能直接读取实例文件、环境变量、数据库或其他插件数据，也不能启动子进程。业务访问、插件存储、网络和模型调用均经过 Go 提供的 SDK。
- Go 从已认证会话确定用户、插件和调用上下文，不接受插件自行指定身份。权限同时受管理员策略、用户授权和当前调用方权限约束。
- 启动默认超时 10 秒，普通工具调用 30 秒，模型调用沿用现有聊天总时限；增加进程内存限制、并发配额、取消和空闲回收。超时及崩溃只使对应插件调用失败。
- 凭据使用现有实例密钥加密，插件通过凭据引用请求宿主向已授权目标注入认证信息；前端插件拿不到明文密钥。

### 前端扩展与管理 API

新增 `/plugins` 插件中心、插件详情页和 `/p/:pluginId/*` 插件页面路由。提供导航、设置面板、统计面板、书签／标签页组操作菜单和背景等固定扩展位置。

- 内置 React 插件按需加载；安装的第三方界面运行在仅允许脚本的沙盒 iframe 中，通过绑定具体 iframe、插件和会话的消息桥调用 SDK。
- 社区主题通过设计变量和限定作用域的样式接入；社区动效通过宿主支持的目标及动画参数接入。背景和自定义交互界面使用沙盒画布或页面。
- 第三方代码不直接操作主应用 DOM。样式禁止远程导入和任意外部资源引用，插件自身资源按已安装版本提供。
- 主题、基础动效方案、背景各自只允许一个当前选择；独立装饰效果可以组合。动效总开关和系统“减少动态效果”始终具有最高优先级。
- 保留核心提供的恢复入口和基础样式；安全模式跳过可选插件，保证插件故障后仍能进入管理页面。

新增 `/api/v1/plugins` 用户接口族，负责目录、运行状态、配置、授权和启停；新增 `/api/v1/plugin-admin` 管理接口族，负责安装来源、安装、更新、回滚、实例禁用和卸载。插件管理仅接受登录会话，安装操作还须通过现有管理员判定。

## 五个实施阶段

### 1. 建立插件内核、存储和开发 SDK

新增数据库迁移，分别保存实例安装版本、用户启用与配置、权限授权、加密凭据、插件独立存储及操作记录。插件数据按用户和插件隔离，外部调用期间不持有 SQLite 事务。

实现统一注册表、依赖解析、生命周期和宿主服务接口。SDK 提供配置、存储、业务能力、网络代理、模型调用、工具注册及清理回调。

提供三个可运行示例：主题／动效插件、沙盒页面插件、服务端工具插件；配套中文开发文档、构建打包和清单校验命令。首版不允许插件执行任意 SQL 迁移，配置升级必须通过新 Schema 校验，不兼容时提示重新配置。

**阶段验收：**示例插件能够注册、启用、调用和完整停用；故障插件不会阻止主应用启动。

### 2. 上线插件中心和安装更新流程

插件中心提供“已安装、内置、官方、社区”视图，以及能力筛选、搜索、详情、权限说明、设置、运行状态和脱敏错误记录。普通用户选择管理员已安装的插件，管理员额外看到安装与维护入口。

- 市场使用随版本分发的目录快照，并支持刷新官方 HTTPS 目录；社区收录通过目录条目审核。管理员添加的自定义来源始终标记为社区来源。
- GitHub 安装固定到具体 Release 资产；离线安装接受标准插件 ZIP。均记录版本和内容摘要，并校验兼容性、路径穿越、符号链接、文件数量及解压大小。
- 安装只使插件在实例中可用，用户授权后才启用。新增权限的升级进入待授权状态，不能继承旧版本未拥有的权限。
- 更新先暂存并检查，再切换版本；保留上一版本及配置快照用于回滚。配置校验失败时不覆盖现用版本。
- 停用和卸载默认保留用户配置及插件数据；清除数据是独立操作。内置插件可停用，但不能从安装目录删除。

**阶段验收：**市场、GitHub 和 ZIP 三条安装路径全部走通，并完成升级失败回退、权限增加和离线使用测试。

### 3. 迁移主题、动效和现有视觉功能

将经典主题、VibeHub、UI/UX Pro、配色方案、基础交互动效、主题切换动画、海洋背景、光标效果、标签热度、悬浮卡片、URL 隐私效果和动态图标迁为内置插件或插件贡献项。

- 主题选择、配色和动效总开关保留便捷入口，内容从插件注册表生成；详细配置统一进入插件详情。
- 原实验功能上下文改为读取插件贡献，移除主程序对具体效果的硬编码依赖。
- 升级按现有有效配置初始化插件状态，保持用户当前外观和开关。
- 海洋背景继续保留账号与浏览器两种保存方式；本地配色和海洋选择按原语义迁移，不擅自改成账号同步。
- 旧偏好字段与接口保留兼容适配，由同一配置服务处理新旧入口，避免双份状态漂移。
- 公开分享页保留现有内置展示效果；第一版不在匿名页面执行第三方插件脚本。

**阶段验收：**升级前后外观与偏好一致；切换账号、公开分享、移动端、减少动态效果和插件停用均无样式或事件残留。

### 4. 迁移 Agent、模型供应商和对外 MCP

把现有站内助手、模型协议适配、书签与标签工具、Agent REST 入口、MCP 服务分别注册为内置插件，共享同一个工具注册表。

- 模型供应商接口统一模型列表、连接测试和对话调用；先迁移现有供应商与自定义地址，保留当前模型、提示词和密钥。
- Agent 接口使用宿主提供的模型与工具能力；聊天请求增加可选 `agentId`，未传时使用原内置助手。
- 保留现有 Agent REST 地址、`/api/mcp`、内置工具名称和响应兼容性。停用对应插件后，由服务端拒绝调用。
- 第三方工具使用插件命名空间，不能覆盖内置工具；所有调用统一检查启用状态、授权、参数和调用方权限。
- 站内写操作继续产生确认卡片；第三方及外部工具默认要求确认，只有用户明确批准的只读工具才可自动运行。第三方自报的只读标记不直接决定执行策略。
- 确认凭证绑定用户、工具、参数、插件版本和配置代次；升级、停用、撤权或相关配置变化后，旧确认凭证失效。
- 第三方工具默认仅在站内使用。用户明确选择对外开放后，仍需 API Key 的工具允许列表授权；现有 Key 不自动获得新工具权限。

扩展现有调用统计，增加插件、工具来源及外部连接维度，保留原统计口径；不记录密钥、聊天正文和工具参数。

**阶段验收：**现有聊天、确认、Agent API 和 MCP 客户端继续工作；新增 Agent、供应商和工具无需修改核心分发逻辑。

### 5. 接入外部 MCP 并完成交付验证

新增内置 MCP 客户端插件，支持 Streamable HTTP 与旧式 HTTP/SSE；每个用户独立管理连接、凭据和可用工具。

- 第一版认证支持无认证、Bearer Token 和 API Key 请求头；OAuth 登录与 stdio 留到后续扩展。
- 实现初始化、工具发现、工具变化刷新、超时、取消、断线重连和会话清理。工具支持分页发现，按连接隔离名称。
- 默认只允许访问公网 HTTPS 服务；内网地址由管理员按目标明确放行。每次连接、DNS 解析和重定向均执行目标检查，凭据不跨目标转发。
- 外部工具进入同一工具注册表，受用户工具选择、Agent 确认和统计约束；重新通过本站 MCP 暴露仍需单独授权。
- 交付一份可安装的官方示例包，验证第三方作者通过 SDK 构建、安装和运行插件的完整流程。

同步维护中英文界面文案、中文开发与部署文档、Agent 接口文档、备份说明及 CI。完整备份纳入插件包和插件配置；业务 JSON 导出不包含插件密钥。

## 测试与验收标准

- **生命周期：**依赖缺失、循环依赖、版本不兼容、启动失败、超时、崩溃、停用清理、更新回滚以及主程序重启恢复。
- **权限与隔离：**普通用户不能安装；跨账号与跨插件访问失败；沙盒消息伪造失败；读取宿主文件、包外导入、直接联网和启动进程失败；安装路径穿越与网络地址绕过被拒绝。
- **兼容迁移：**旧数据库和浏览器偏好可重复迁移；AI 密钥可继续使用；旧 API、工具名、确认卡片和统计口径保持兼容。
- **交互与恢复：**桌面及移动端安装、授权、配置和启停可用；主题恢复、减少动态效果、安全模式和故障面板可用。补充浏览器集成测试验证真实 iframe 与消息桥。
- **Agent/MCP：**两个用户连接同一 MCP 时凭据和工具隔离；重名工具可区分；撤权立即生效；旧确认凭证不可重放；外部工具不会自动出现在既有 API Key 下。
- **工程检查：**执行前端类型、规范、测试及构建，Go 格式、编译、静态分析、测试和漏洞检查；验证 Linux amd64/arm64 镜像及 Windows 原生脚本宿主。

当前已验证的基线为：主题、动效和海洋背景相关 **20 个前端测试通过**，现有 MCP 权限与调用统计专项测试通过。上述五阶段全部验收后，才视为本次插件化完成。

## 实施约定与参考依据

- 保留当前工作区已有的搜索栏修改和 `.pi/` 内容。
- 数据库只追加迁移；本次不修改独立浏览器扩展仓库。若后续实际改动扩展，单独按其发布规则递增版本。
- 每批提交推送前按仓库规则递增版本末段，并核对远端；本规划阶段不修改版本、不提交或发布。
- 使用 Magpie 源码片段时保留 MIT 许可与署名；插件 SDK 不承诺其他应用插件的直接兼容性。
- 参考 [Magpie 插件内核](https://github.com/yetone/magpie/blob/083821dc96d4542a730b96a21e1b7fe7df9d15d1/docs/subsystems/plugin-runtime.md)、[插件工具机制](https://github.com/yetone/magpie/blob/083821dc96d4542a730b96a21e1b7fe7df9d15d1/docs/subsystems/plugin-tools.md)及 [Deno 权限模型](https://docs.deno.com/runtime/fundamentals/security/)。
